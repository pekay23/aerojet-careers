Email

The portal uses Resend for transactional email.

01 · Core functions

Core functions

sendEmail(to, subject, html, from?)

Sends a single email via Resend. Falls back to EMAIL_FROM if no sender is specified.

sendBulkEmails(recipients, subject, html, from?)

Sends the same email to multiple recipients. Processes in batches to avoid rate limits.

02 · Retry strategy

Retry strategy

Both functions implement a 3-attempt backoff:

  1. First attempt: immediate
  2. Second attempt: 1 second delay
  3. Third attempt: 2 seconds delay

Failures after 3 attempts are returned to the caller.

03 · Templates

Templates

Email templates are stored as React components in app/admin/settings/email-templates/ and rendered server-side before sending.

Current templates:

  • Application acknowledgment — sent automatically on application submit
  • Status change notification — sent when admin updates application stage
  • Credentials — sent when admin creates a new staff member
04 · Logging

Logging

Every send is logged to the email_logs table:

email_logs
  id          uuid
  recipient   text
  subject     text
  provider_id text       -- Resend message ID
  status      text       -- sent, delivered, bounced, failed
  error       text       -- provider error message
  sent_at     timestamptz
05 · Acknowledgment flow

Acknowledgment flow

POST /api/applications
  → validate + insert application
  → POST /api/email/acknowledge
    → render acknowledgment template
    → sendEmail(applicant.email, subject, html)
    → insert email_log

Email failures are non-blocking — the application is still created even if the acknowledgment fails.
