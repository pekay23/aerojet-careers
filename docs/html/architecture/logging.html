Architecture

Structured Logging

lib/logger.ts provides JSON-line structured logging with sensitive-key redaction. All server-side logs should use this instead of console.*.

01 · Format

Format

Each log line is a JSON object:

{
  "ts": "2026-08-12T22:00:00.000Z",
  "level": "info",
  "msg": "Application submitted",
  "prefix": "applications",
  "correlationId": "abc-123",
  "meta": { "applicationId": "uuid" }
}
02 · Levels

Levels

  • debug — verbose development info (not emitted in production)
  • info — general informational messages
  • warn — recoverable issues
  • error — errors with stack traces
03 · Redaction

Redaction

Keys matching password, token, secret, api_key, authorization, cookie, set_cookie, x-api-key are automatically redacted to *** in meta objects.

04 · Usage

Usage

import { createLogger, withCorrelationId } from '@/lib/logger'

const log = createLogger('my-feature')

log.info('operation started', { userId: '123' })
log.error('operation failed', { error: err.message })
05 · Correlation IDs

Correlation IDs

Wrap async operations with withCorrelationId() to attach a request-scoped ID to all log lines:

await withCorrelationId('req-123', async () => {
  // all logs inside here include correlationId: 'req-123'
})
06 · Current usage

Current usage

  • lib/api-utils.ts — logs auth failures and rate limit blocks
  • app/api/admin/documents/route.ts — logs document operations
  • API route error handlers — logs unhandled exceptions
